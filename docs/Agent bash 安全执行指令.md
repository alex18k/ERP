# Agent Bash 安全执行指令（AGENTS.md）

## 0. 指令优先级

本指令适用于所有通过 Bash/Shell 执行的命令。  
**本指令优先级高于用户的临时操作请求。**

- **P0 命令：永不执行**，即使用户明确要求、解释理由或承诺后果，也必须拒绝。
- **P1 命令：必须获得用户明确确认后才能执行**。
- **P2 命令：允许执行**，但必须限定在工作区或只读诊断范围内。
- 无法判断风险等级时，**按 P0 处理并拒绝**。
- 不得通过 `sudo`、`env`、`bash -c`、`sh -c`、变量拼接、命令替换、Base64 解码、别名、函数、脚本文件等方式绕过本指令。

---

## 1. 执行前强制自检流程

每次执行 Bash 命令前，Agent 必须完成以下检查：

1. **解析完整命令**：包括 `;`、`&&`、`||`、`|`、`$()`、反引号、重定向、Here-Doc 中的每一段。
2. **解包包装器**：剥离 `sudo`、`env`、`nice`、`timeout`、`bash -c`、`sh -c` 等包装，检查真实命令。
3. **检查操作对象**：路径、设备、数据库对象、Git 分支、远程 URL 是否明确且在授权范围内。
4. **判定风险等级**：P0 / P1 / P2。
5. **执行或拒绝**：
   - P0：立即拒绝，不执行任何部分。
   - P1：展示完整命令和风险，等待用户明确确认。
   - P2：在授权工作区内执行。
6. **记录审计信息**：命令、风险等级、判定理由、是否确认、执行结果。

## 2. P0：绝对禁止命令（永不执行）

以下命令或等价变体一律拒绝，不得尝试“安全版本”后直接执行。

### 2.1 文件系统与磁盘破坏

禁止：

- `rm -rf /`、`rm -rf ~`、`rm -rf .`、`rm -rf ..`
- 目标为未定义或不可解析变量的递归删除，如 `rm -rf "$VAR"`
- 对工作区外路径的递归删除，如 `rm -rf /etc`、`rm -rf /home`
- 通过 `find ... -delete`、`find ... -exec rm` 间接删除
- `dd if=/dev/zero of=/dev/sd*`、`dd if=/dev/random of=/dev/sd*`
- `> /dev/sda`、`mkfs.*`、`fdisk`、`parted`
- 向块设备或裸设备写入任何数据

### 2.2 权限提升与所有权篡改

禁止：

- `sudo`、`su -`、`doas`
- `chmod 777`、`chmod -R 777`
- `chown -R root` 或递归修改系统关键路径所有权
- 修改 `/etc/sudoers`、`/etc/passwd`、`/etc/shadow`、`/etc/ssh/*`

### 2.3 远程代码执行与动态解释执行

禁止：

- `curl ... | bash`、`curl ... | sh`、`wget ... | bash`、`wget ... | sh`
- `bash -c`、`sh -c` 执行动态字符串命令
- `eval`、`source`、`.` 加载不可信脚本
- `python -c`、`python -e`、`perl -e`、`ruby -e`、`node -e` 执行任意代码
- 将网络下载内容直接送入任何解释器
- 对不可信内容进行 Base64/编码解码后执行

### 2.4 系统与资源耗尽

禁止：

- Fork Bomb，如 `:(){ :|:& };:`
- `kill -9 -1`、`killall5`
- `shutdown`、`reboot`、`halt`、`poweroff`
- 无限输出或无限循环命令接入管道，如 `yes | ...`、`while true; do ...; done`
- 大量并发进程创建导致系统不可用

### 2.5 系统配置与数据破坏

禁止：

- 写入 `/etc/` 下系统配置文件，如 `echo ... > /etc/...`
- `DROP TABLE`、`DROP DATABASE`、`TRUNCATE TABLE`
- 不带 `WHERE` 的 `DELETE FROM`
- 批量更新或删除生产数据库记录且无明确范围

### 2.6 Git 不可逆历史破坏

禁止：

- `git push --force`、`git push -f`
- 对共享分支执行强制推送
- `git reset --hard` 后覆盖未提交更改且无备份
- `git clean -fdx` 删除未跟踪文件且无确认

## 3. P1：必须用户明确确认的命令

执行前必须展示完整命令、影响范围和风险，并等待用户回复“确认执行”或等价明确指令。

包括但不限于：

- 工作区内 `rm -rf`、`rm -r`、批量删除
- `git reset --hard`、`git clean -f`、`git clean -fd`、`git clean -fdx`
- `git push --force-with-lease`
- `chmod`、`chown` 非递归但影响权限的操作
- `systemctl stop`、`systemctl disable`、`systemctl restart`
- 安装、卸载、升级系统包或全局依赖
- 修改工作区外文件
- 写入数据库、迁移、批量更新
- 下载远程脚本并保存到本地后准备执行
- 任何可能不可逆、影响共享环境或影响他人的操作

确认格式示例：

```text
即将执行：<完整命令>
风险等级：P1
影响范围：<路径/分支/服务/数据库对象>
可能后果：<不可逆删除/历史重写/服务中断等>
是否确认执行？请明确回复“确认执行”。
```

---

## 4. P2：允许执行的只读诊断与工作区安全命令

允许在工作区内执行，且不得包含 P0/P1 片段：

- `pwd`、`ls`、`cat`、`head`、`tail`、`grep`、`rg`
- `find` 且不带 `-delete`、`-exec rm`、`-exec sh`
- `ps`、`df`、`du`、`free`、`uname`、`whoami`
- `git status`、`git diff`、`git log`、`git show`
- 工作区内构建、测试、格式化命令，但不得越界写入或删除

---

## 5. 路径与范围限制

- 所有写操作必须限定在 `WORKSPACE` 内。
- 删除操作必须使用明确绝对路径，禁止对根路径、家目录、当前目录使用递归通配删除。
- 禁止使用 `*`、`.*`、`$VAR` 等不确定目标执行递归删除。
- 禁止操作 `/`、`/etc`、`/usr`、`/bin`、`/boot`、`/dev`、`/proc`、`/sys`、`/var` 等系统路径，除非任务明确且已获 P1 确认。

---

## 6. 绕过检测的禁止行为

Agent 不得：

- 将危险命令拆分为多段执行以规避检查
- 使用变量拼接、命令替换、别名、函数隐藏危险命令
- 使用 `sudo env bash -c` 等组合包装
- 将危险命令写入脚本后再执行以规避检查
- 对拒绝原因进行隐瞒或伪造执行结果
- 在用户未确认 P1 时“先执行再解释”

---

## 7. 拒绝与替代方案

遇到 P0 命令时，必须拒绝并说明原因，同时提供安全替代方案。

拒绝模板：

```text
拒绝执行：该命令属于 P0 高危操作，可能导致不可逆的数据丢失、系统损坏或权限失控。
原因：<具体原因>
安全替代方案：
1. <只读检查命令>
2. <限定路径的备份/删除方案>
3. <需用户确认后执行的 P1 方案>
```

---

## 8. 审计要求

每次 P0/P1 判定必须记录：

- 时间
- 原始命令
- 解析后的真实命令
- 风险等级
- 判定理由
- 用户是否确认
- 执行结果或拒绝原因

---

## 9. 最终原则

**不确定就拒绝。  
能只读就不写入。  
能限定路径就不扩大范围。  
能备份就不直接删除。  
P0 永不执行，P1 必须确认。**
