# 生产订单取消逻辑变更记录

记录日期：2026-09-13
涉及模块：生产管理 / 生产订单、加工单、销售订单状态联动

## 1. 背景与问题

生产订单页原本的「取消」按钮不生效：

- 前端 `handleCancel` 调用 `productionApi.updateOrder(id, { status: 'cancelled' })`
- 但后端 `updateProductionOrder` 只处理 `quantity / planStartDate / planEndDate / remark`，**完全忽略 `status`**
- 结果：接口返回成功、前端弹出「已取消」，但生产订单状态不变，关联加工单也不变。

## 2. 变更目标

让生产订单「取消」真正生效，并保证关联数据一致：

- 生产订单置为 `cancelled`
- 未完成的加工单同步作废
- 若该销售订单不再有任何有效生产订单，则回退销售订单状态，便于重新 MRP / 排产

## 3. 入口

| 层 | 位置 |
| --- | --- |
| 页面按钮 | 生产订单页「取消」，仅 `planned` / `in_progress` 显示（`client/src/views/production/order/index.vue`） |
| 前端 API | `productionApi.cancelOrder(id)` → `PUT /api/v1/production/orders/:id/cancel`（`client/src/api/index.ts`） |
| 路由 | `server/src/routes/production.routes.ts`，权限 `production:manage` |
| 控制器 | `production.controller.ts` → `cancelOrderHandler` |
| 服务 | `production.service.ts` → `cancelProductionOrder` |

## 4. 处理逻辑

`cancelProductionOrder(id)` 在一个数据库事务内执行：

1. **校验**
   - 生产订单不存在 → 报错
   - 已是 `cancelled` → 报错「生产订单已取消」
   - 已是 `completed` → 报错「已完成的生产订单不能取消」
2. **作废未完成加工单**
   - `WorkOrder` 中 `productionOrderId = id` 且状态属于 `pending / in_progress / paused` 的记录 → `cancelled`
   - 已完成（`completed`）或已取消（`cancelled`）的加工单不动
3. **生产订单置取消**
   - `ProductionOrder.status` → `cancelled`
4. **销售订单回退（有条件）**
   - 若该生产订单关联销售订单，且该销售订单下**已无** `planned / in_progress` 的生产订单：
     - 销售订单 `status` → `confirmed`
     - 对应销售明细（`orderId` + 相同 `materialId`，且状态为 `in_production`）→ `pending`
   - 若该销售订单下仍有其他有效生产订单，则销售订单状态**不回退**

## 5. 状态流转

```
生产订单:  planned / in_progress  --取消-->  cancelled
加工单:    pending / in_progress / paused  --取消-->  cancelled
销售订单:  in_production  --(该销售订单已无有效生产订单)-->  confirmed
销售明细:  in_production  --(同上)-->  pending
```

## 6. 边界与不回滚项

- 已完成的生产订单不可取消。
- 已完成 / 已取消的加工单不受影响。
- **库存、报工记录不做回滚**：已产生的报工数量、库存流水保留。
- 销售订单回退仅在「无其他有效生产订单」时发生，避免误改仍在生产中的订单。

## 8. 同期相关变更（生产订单）

- **防重复下达**：`createProductionOrders` 在下达时，若已存在「同物料 + 同销售订单 + `planned/in_progress`」的生产订单则跳过；返回 `{ created, skipped }`。
- **下达弹窗置灰已下达**：新增 `GET /api/v1/production/orders/issued-keys` 返回未完成生产订单的 `物料 + 销售订单` 键；「从 MRP 建议下达」弹窗据此将已下达项标记为「已下达」并禁用勾选。

## 9. 取消后重新排产（允许重排并重建加工单）

生产订单被取消后，允许重新排产，并重建加工单。

### 排产校验（`scheduleProduction`）

- 已完成（`completed`）的生产订单不能排产。
- 已存在**未取消**的加工单（`status != cancelled`）时，视为已排产，拒绝重复排产（防重复）。
- 若已取消的加工单中**存在报工记录**，拒绝重新排产（避免误删历史报工），提示人工处理。

### 重建流程

重新排产时，在事务内：

1. 删除该生产订单下**已取消**的加工单及其 `ProcessRouteAssignment`
2. 按物料绑定的工艺路线逐工序重新生成加工单（一序一张，`pending`）
3. 生产订单状态 → `in_progress`，记录 `actualStartDate`
4. 关联销售订单 → `in_production`，对应明细 → `in_production`

### 前端

生产订单页「排产」按钮在 `planned` 与 `cancelled` 状态均显示（`client/src/views/production/order/index.vue`）。

### 验证

用临时生产订单实测：

1. 创建临时单（`planned`）
2. 排产 → 生成 3 张加工单（`pending`）
3. 重复排产 → 被拒绝「该生产订单已排产，不能重复排产」
4. 取消 → 加工单全部 `cancelled`
5. 重新排产 → 旧 `cancelled` 加工单被清除，重新生成 3 张 `pending`
6. 清理临时数据

## 10. 生产订单计划字段与排产前置条件

### 新增字段（`ProductionOrder`）

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `planner` | `String?` | 计划员 |
| `releaseDate` | `DateTime?` | 下达日期 |

迁移：`20260913060000_add_production_order_planner_release`。

### 下达时自动写入

`createProductionOrders`（从 MRP 建议下达）创建生产订单时，`releaseDate` 自动写为当前时间；`planner` 由输入提供（一般为空，需后续维护）。

### 排产前置条件

`scheduleProduction` 在排产前校验以下字段均已维护，否则报错并阻止排产：

- `planStartDate`（计划开始日期）→「请先维护计划开始日期」
- `planEndDate`（计划结束日期）→「请先维护计划结束日期」
- `planner`（计划员）→「请先指定计划员」
- `releaseDate`（下达日期）→「请先维护下达日期」

### 前端

- 编辑弹窗新增「计划员」「下达日期」字段（连同已有的计划开始/结束），保存写入 `updateProductionOrder`。
- 「计划员」为下拉，选项来自**计划员角色（`Planner`）的启用用户**，接口 `GET /production/planners`（权限 `production:view`），取 `realName || username` 作为值。
- 列表新增「计划员」「下达日期」两列。
- 编辑表单中「计划开始、计划结束、下达日期、计划员」为**必填**：前端 `el-form` 校验，后端 `updateProductionOrder` 同步校验（缺失返回对应提示）。

### 历史数据

- 已存在的生产订单 `releaseDate` 回填为其 `createdAt`（即原下达时间）；`planner` 保持为空，需人工维护后方可排产。

### 验证

用临时生产订单实测：

1. 下达创建 → `releaseDate` 自动写入，`planner` 为空
2. 直接排产 → 被拒绝「请先指定计划员」
3. 编辑填入计划员后 → 排产成功生成 3 张加工单
4. 清理临时数据

## 11. 分批排产（生产订单内批次）

一张生产订单可按数量分成多个批次，每批独立计划日期、独立生成加工单并独立跟踪进度。

### 数据模型

- 新增 `ProductionBatch`：`id / productionOrderId / batchNo / quantity / planStartDate / planEndDate / status(planned,in_progress,completed,cancelled) / remark / createdAt`，`@@unique([productionOrderId, batchNo])`
- `ProductionOrder` 增加 `batches`；`WorkOrder` 增加 `batchId`（关联批次）
- 迁移：`20260913070000_add_production_batch`（历史加工单 `batchId` 为空）

### 排产（`scheduleProduction`）

签名：`scheduleProduction(orderId, userId, batches?)`，`batches: [{ quantity, planStartDate?, planEndDate?, remark? }]`。

- 保留前置校验（计划开始/结束、计划员、下达日期、工艺路线 active）
- 计算已排产量 = 未取消批次数量之和；校验 `本次批次合计 + 已排 ≤ 生产订单数量`，超排报错
- 不传 `batches`：按「剩余未排量」建一个默认批次（剩余为 0 报「已排满」）
- 每批次按 `batchNo`（同订单内 max+1）创建，并为「批次 × 每道工序」生成加工单：`plannedQty`=批次数量、`startTime`=批次计划开始
- 生产订单 → `in_progress`；销售订单 → `in_production`
- 已取消的加工单若带报工则拒绝重建；重建时清理已取消加工单与已取消批次

### 报工与完成（`reportWork`）

- 加工单完成时同步所属批次：该批全部加工单完成 → 批次 `completed`，否则 `in_progress`
- 生产订单完成条件：**全部加工单完成 且 已排产量 ≥ 生产订单数量**；未排满时保持 `in_progress`
- 生产订单完成后按原逻辑关闭销售订单

### 取消（`cancelProductionOrder`）

- 整单取消：未完成加工单与未完成批次一并置 `cancelled`（不做单批取消）

### 前端

- 生产订单页「排产」改为**批次录入弹窗**：批次号/数量/计划开始/计划结束，默认一行 = 剩余量 + 订单计划日期；显示「已排/剩余」，实时校验不超排
- 生产订单列表新增「批次/已排」列
- 加工单列表新增「批次」列（第 N 批）

### 验证

临时生产订单（数量 10000，工艺路线 3 工序）实测：

1. 排第 1 批 4000 → 1 个批次、3 张加工单
2. 再排 7000 → 被拒绝「已排产 4000，本次 7000，超过生产订单数量 10000」
3. 完成第 1 批 → 批次 `completed`，生产订单仍 `in_progress`
4. 排第 2 批 6000 → 3 张加工单
5. 完成第 2 批 → 生产订单 `completed`
6. 清理临时数据



## 12. 批次物料清单 / 生产领料 / 生产入库

排产生成批次时，按产品 BOM 生成批次物料清单；库存管理模块据此领料与成品入库。

### 数据模型

- 新增 `ProductionBatchMaterial`：`id / batchId / materialId / requiredQty / issuedQty / unit / status(pending,partial,issued) / remark`，`@@unique([batchId, materialId])`
- `ProductionBatch` 增加 `receivedQty Float @default(0)`（成品已入库量）
- 迁移：`20260913080000_add_batch_material`

### 生成（排产时）

- `scheduleProduction` 创建每个批次时，读取产品 **active BOM（一层）**，按 `批次数量 × BOM用量 × (1+损耗率)` 生成清单行
- **产品无 active BOM → 拒绝排产**（提示「该产品未维护启用的BOM，无法排产」）

### 生产领料（库存管理 → 生产领料，按生产订单发料）

- 列表：**生产订单**（订单号、产品、数量、批次数、状态），操作栏「发料」
- 发料弹窗：
  - 主表：生产订单信息 + **发放批次**（先选批次）+ **出库仓库**（统一）+ **本次发放数量（成品数量）**
  - 明细：所选批次的物料清单行（需求量/已发/未发），`本次发放数量` 默认 = `单件用量 × 发放数量`（单件用量 = 需求量 ÷ 批次数量），并封顶为未发量；发放数量变化时重算，可手工修改
  - 明细含「库位」列，默认取物料主文件的库位，可修改；发料时写入库存流水 `StockRecord.location`（`StockRecord` 新增 `location` 字段）
  - 提交：**批量发放**，逐行 `stockOut`（`ISS-WO`，`relatedType="ProductionBatch"`，`relatedId=batchId`），累加 `issuedQty`、状态 `pending → partial → issued`
  - 异常行**跳过**（数量≤0、超过未发量、库存不足），返回 `{ documentNo, issued, skipped }` 并提示

### 生产入库（库存管理 → 生产入库）

- 列表：可入库批次（可筛选仅未入库完 / 全部）
- 入库：`stockIn`（事务类型 `RCT-WO`，`relatedType="ProductionBatch"`），物料 = 生产订单产品，数量默认剩余（批次数量 − 已入库），可改；累加 `receivedQty`
- 校验：不超剩余可入库量、批次已取消不可入库

### 接口

| 方法 | 路径 | 权限 |
| --- | --- | --- |
| GET | `/production/batch-materials` | `production:view` |
| GET | `/production/batches/:id/materials` | `production:view` |
| POST | `/production/batches/:id/issue` | `stock:edit` |
| GET | `/production/batches/receivable` | `production:view` |
| POST | `/production/batches/:id/receive` | `stock:edit` |

### 前端

- 库存管理菜单新增「生产领料」（`/inventory/issue`）与「生产入库」（`/inventory/production-receive`）
- 发料弹窗先选批次，主表统一选出库仓库；入库弹窗按产品库位（`material.location` 映射同编码仓库）预选仓库，可改

### 历史数据

- 已存在但无物料清单的批次，按产品 active BOM 回填了批次物料清单（本次为 2 个批次各 15 行）

### 验证

临时生产订单（数量 1000，产品 BOM 15 项）实测：

1. 排产 → 生成 1 个批次、15 行物料清单
2. `GET /batches/:id/materials` → 返回批次与 15 行清单
3. 批量发料：1 行正常发放、2 行异常（超未发量、物料行不存在）被跳过；`issuedQty=5`、状态 `partial`、库存 20000 → 19995
4. 入库 5 → `receivedQty=5`、产品库存增加
5. 清理临时数据

## 13. 库存按仓库记账 & 采购收货入库库位

### 问题
采购收货弹窗选择库位 `A01 材料仓`，但库存实际入到了 `WH-01 原料仓库`。原因：`Stock.materialId` 存在历史遗留的 `@unique` 索引，导致每个物料只能有一条库存行（无法按仓库/库位分别记库存），收货只能落到已有库存行所在仓库。

### 变更
- 移除 `Stock.materialId` 唯一约束，保留 `@@unique([materialId, warehouseId])`；同一物料可在多个仓库/库位分别记库存
- 迁移：`20260913100000_stock_multi_warehouse`（`DROP INDEX Stock_materialId_key`）

### 采购收货入库库位
- 收货弹窗的「库位」（默认取物料主文件库位）映射到**同编码的仓库**（如 `A01` → `A01 材料仓`），收货库存记入该仓库
- 库位无对应仓库时，退回原逻辑（已有库存行 / 第一家启用仓库）

### 兼容调整（多仓库库存）
- 物料列表/导出：现存量按物料**汇总**多个仓库库存
- 库存预警、管理驾驶舱低库存、库存报表：先按物料汇总再判断/统计
- 销售发货出库：从**有库存**的仓库行扣减

### 数据修正
- `PO202609130005` 两行收货流水原记入 `WH-01`，已按库位 `A01` 更正到 `A01 材料仓`，并同步移动对应库存
