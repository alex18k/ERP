# MRP 运算逻辑说明

记录日期：2026-09-13（最近更新 2026-09-17）
代码位置：`server/src/services/mrp.service.ts`

## 0. 变更记录

| 日期 | 变更 |
| --- | --- |
| 2026-10-18 | **需求日期逐层下推**：BOM 展开时，子件需求日期 = 父件需求日期 − 父件生产提前期（父件为制造件时）。即采购件需求日期 = 销售交货期 − Σ 路径上各制造件层级的生产提前期；`orderDate` 仍在此基础上再减本件提前期 |
| 2026-10-18 | **采购建议单价改用 `Material.price`（最近采购价）**，无值回退加权平均成本 `cost`；转采购单明细单价取建议单价 |
| 2026-09-17 | 新增 `deductInProcess` 参数：扣除**在制量**（未完工生产订单未入库量）与**已发料量**（已按生产订单发放的承诺量）；生产建议量改为 `订单需求 − 该(物料×订单)在制剩余量 − 成品/半成品现库存` |

## 1. 取数（输入）

- **销售订单**：状态为 `confirmed` / `in_production`（接口可传 `orderIds` 指定范围，不传则全部）
- **订单明细**：状态为 `pending` / `in_production`
- **运算参数**（`MrpParams`）：

| 参数 | 默认 | 说明 |
| --- | --- | --- |
| `deductStock` | `true` | 是否扣除现有库存 |
| `deductInTransit` | `true` | 是否扣除在途采购量 |
| `deductInProcess` | `true` | 是否扣除在制量（未完工生产订单未入库量 + 已发料量，2026-09-17 新增） |
| `considerSafetyStock` | `true` | 是否考虑安全库存 |

> 前端 MRP 运算页提交 `{}`，即四项默认都参与。

## 2. BOM 递归展开（`expandDemand`）

- 从销售订单产品开始，逐层展开该产品的 **active BOM**（`Bom.status = "active"`）
- 每项用量 = 父需求 × BOM 用量 × (1 + 损耗率 `lossRate`)
- 若子件**自身还有 BOM** → 记为**半成品**（`isSemiProduct = true`）并继续向下展开
- 若无子 BOM → 作为叶子需求
- 订单产品自身也计入需求（用于跟踪）
- **需求日期逐层下推**（参照金蝶云/用友规则）：子件需求日期 = 父件需求日期 − 父件生产提前期（仅当父件 `category = manufacture`，提前期取 `manufactureLeadTime ?? leadTime`，无则 0 不偏移）；该日期既作为子件自身需求日期，也继续向下层传递
  - 源单为销售订单（成品自身/顶层采购件）：需求日期 = 销售订单明细行交货期（回退主表交货期）
  - 源单为上层生产/加工单（下层子件）：需求日期 = 上层需求日期 − 上层生产提前期
  - 例：销售交货期 D、成品生产提前期 5 天 → 直接采购子件需求日期 = D−5；再下一层子件 = D−5−该层生产提前期，依此累加
- 保护：最大深度 `MAX_BOM_DEPTH = 20`；检测到循环引用时报错
- 汇总为 `demandMap`：`物料 → 订单 → 数量`

> 制造件参与程度：半成品/成品的 `isSemiProduct = true` 会进入缺料清单并能出生产建议；**叶子制造件**（无自身 active BOM）`isSemiProduct = false`，只进缺料清单、不出生产建议。制造件本身不产生采购建议（其采购件子件才产生）。

## 3. 可用量

- **现存量**：`Stock` 在**启用仓库**（`Warehouse.status = 1`）中按物料合计
- **在途**：`PurchaseOrderItem` 状态为 `pending` / `partial_received` 且所属采购单未取消，数量 = `数量 − 已收`
- **在制量（在途供给）**：`ProductionOrder` 状态为 `planned` / `in_progress` 的未完工生产订单，按物料合计 `订单数量 − 已完工入库量`（已入库量 = 该订单**未取消批次**的 `receivedQty` 之和）。即未完工生产订单还在"路上"的产出
- **已发料量（承诺量）**：`ProductionBatchMaterial.issuedQty` 合计（仅统计**未取消批次**、且所属生产订单 `planned` / `in_progress`）。这些物料已按生产订单发料、库存已扣且不会退回，视为已经承诺消耗

> 说明：取消批次 / 已完工生产订单不计入在制与已发料（其发料量视为已消耗，继续按当前库存反映需求）。

## 4. 净需求（按订货周期分桶）

- 按物料的 `orderCycleDays` 对需求分桶：与桶内**最早需求日期间隔在周期内**的合并，超出则新开一桶
- 需求日期见「2. BOM 递归展开」：顶层取**销售订单明细行**的交货期 `SalesOrderItem.deliveryDate`（明细行无交货期时回退订单主表 `SalesOrder.deliveryDate`），子件再逐层减去各制造件父件的生产提前期；同一订单不同交货期的明细行按各自日期参与分桶
- 库存 / 在途 / 在制 / 已发料按需求日期**由早到晚依次冲抵**
- **安全库存只计入最早一个桶**，且**先并入需求再冲抵**：

```
净需求 = max(0, 毛需求 + 安全库存 − 库存 − 在途 − 在制量 − 已发料量)
```

> 说明：安全库存先并入需求、再用库存/在途/在制/已发料冲抵，避免剩余库存无法覆盖安全库存导致重复建议。

## 5. 输出与落库

- **缺料清单**：每个需求桶一条（毛需求、可用库存、在途、在制量、已发料量、安全库存、净需求、影响订单；`wipQuantity`/`issuedQuantity` 仅存于 `result` JSON，未落库到 `MrpShortage` 表）
  - 制造件有库存照常参与：库存/在制/已发料冲抵后净需求≤0 则整行不列出
- **采购建议**：`shortages` 中 `category = purchase` 的物料
  - 建议量 = 净需求（保留 2 位小数）
  - **建议单价** = `Material.price`（最近采购价，采购收货回写），无值回退 `Material.cost`（移动加权平均成本）；转采购单时明细单价 = 建议单价（再回退物料 price/cost）
   - 供应商、提前期取物料主文件；需求日期 = 桶需求日期（已含上层各制造件生产提前期偏移）；`orderDate`（建议下单日期）= 需求日期 − **本件采购提前期**（`PurchaseSuggestion.orderDate` 字段落库）；`purchaseOverdue = orderDate < 今天` 标记需立即下单。最终下单日期 = 销售交货期 − Σ上层制造件生产提前期 − 本件采购提前期
  - **会合并**：同一物料的不同订单需求经订货周期分桶，周期内合并为同一条建议
- **生产建议**：`isSemiProduct = true 且 category = manufacture` 的物料
  - **不合并**：按（物料 × 订单）逐行生成，相同物料不同订单各一条建议
  - 每条独立 `relatedOrderId` / `orderNo` / `customerName`，便于按订单下达与显示客户名称
   - `needDate`（需求交期）= 关联订单明细行交货期（回退主表交货期）**减去路径上各制造件父件的生产提前期**（见「2. BOM 递归展开」）；`orderDate`（建议开工日期）= `needDate` − 该物料生产提前期（`manufactureLeadTime ?? leadTime` 天）；无交货期则均为空；`overdue = orderDate < 今天` 时标记来不及排产
   - **在制量冲抵**：该（物料 × 销售订单）已下达未完工生产订单的剩余量，从建议量中扣除，不再重复建议（如已排产并生产中的半成品不再重复出生产建议）。无关联销售订单的手工生产订单剩余量也按物料合计冲抵（需求日期早的订单优先分配）
  - **已入库/现库存冲抵**：成品、半成品**现有库存**从建议量中扣除（现库存含生产入库 RCT-WO 的成品；按物料共用，需求日期早的订单优先分配），库存充足则不再建议生产
  - **生产建议量 = max(0, 订单需求 − 在制剩余量 − 现库存)**，扣减后为 0 的建议不生成
  - `GET /mrp/history/:id` 读取时优先用存储的 `needDate`（含生产提前期偏移）；旧运行结果（`result` JSON 无 `needDate`）才回退销售订单交货期补全，无需重跑 MRP
- 落库：
  - 创建 `MrpRun`（含 `result` JSON：shortages / purchaseSuggestions / productionOrders）
  - 写入 `MrpShortage` 缺料明细
  - **先把所有 `pending` 采购建议置为 `cancelled`**，再创建新的 `PurchaseSuggestion`（`status = pending`）

## 6. 后续流转

- **采购建议 → 采购单**：采购建议页勾选 → `POST /mrp/suggestion/generate-purchase`
  - 勾选的建议按**供应商**分组，同一供应商合并为一张采购单（`status = draft`）；不同需求日期在明细行的 `expectedDate` 区分
  - 关联建议置为 `converted`
- **生产建议 → 生产订单**：从 MRP 建议下达生产订单 → 排产（按工艺路线生成批次与订单级工艺路线，报工直接挂批次工序）

## 7. 安全库存检查（独立于 MRP）

- 接口：`POST /mrp/safety-stock-suggest`（权限 `purchase:create`）
- 逻辑：扫描**采购件**（`category = purchase`、`status = 1`、`safetyStock > 0`），当
  `现存量 + 在途 < 安全库存` 时生成采购建议，数量 = 缺口
- 需求日期 = 今天 + 采购提前期
- **去重**：该物料已有 `pending` 采购建议则跳过
- 来源标记：`listShortages` 返回的建议带 `source`（`mrp` = MRP 需求，`safety` = 安全库存）

## 8. 接口一览

| 方法 | 路径 | 权限 | 说明 |
| --- | --- | --- | --- |
| POST | `/mrp/calculate` | `mrp:run` | 执行 MRP 运算 |
| GET | `/mrp/history` | `mrp:view` | 运算历史 |
| GET | `/mrp/history/:id` | `mrp:view` | 某次运算结果 |
| GET | `/mrp/shortage` | `mrp:view` | 最新缺料榜 + 采购建议 |
| POST | `/mrp/suggestion/generate-purchase` | `purchase:create` | 采购建议转采购单 |
| POST | `/mrp/safety-stock-suggest` | `purchase:create` | 安全库存检查生成采购建议 |

## 9. 重要注意事项

1. **只对有毛需求的物料计算**：无销售需求但低于安全库存的物料不会出现在 MRP 结果中，需用「安全库存检查」
2. **安全库存是兜底**，不是独立的自动补货逻辑
3. **每次 MRP 运行会取消所有 `pending` 采购建议**（包括安全库存来源的），推荐顺序：先跑 MRP → 再做安全库存检查 → 转采购单
4. **订货周期分桶**会影响建议的拆分与需求日期
5. 现存量仅统计**启用仓库**；停用仓库库存不参与
6. **在制量/已发料量仅统计未取消批次与未完工生产订单**（`planned`/`in_progress`），避免重复采购/重复排产：发了料但生产订单未完工入库时，再跑 MRP 不会对已发料物料重复产生采购建议、也不会对在制半成品重复产生生产建议
7. **生产建议量 = 需求 − 该（物料×销售订单）在制剩余量 − 手工生产订单在制剩余量 − 成品/半成品现有库存**（现库存含生产入库量，需求日期早的订单优先分配）；已取消批次不计入，其已发料视为消耗、按当前库存继续反映需求
8. **成品入库 ≠ 退出 MRP**：生产入库（RCT-WO）只增加现存量，不会关闭销售订单；销售订单需经**报工**把全部未取消批次完工（且已排产量≥订单量）才自动置 `completed`，从而退出 MRP 取数。因此在制品入库后、订单未完工前重跑 MRP：成品缺料被现库存覆盖、生产建议被库存+在制扣减，不会重复建议
9. **制造件**：参与毛需求展开、缺料清单与生产建议，不产生采购建议；叶子制造件（无自身 BOM）不出生产建议
