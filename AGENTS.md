# AGENTS.md

ERP生产管理系统 (MRP-driven manufacturing ERP). Monorepo with two apps at the repo root: `server/` (Node + Express 5 + Prisma) and `client/` (Vue 3 + Vite 8 + Element Plus). Conversation/docs language is Chinese (订单/物料/排产/报工). Root design docs are the source of truth for requirements: `erp.md` (original ask), `ERP系统设计说明.md`, `ERP项目开发计划.md`. This repo is NOT a git repo.

## Run / verify

```bash
# backend  (port 3000) — ALWAYS use tsx
cd server && npm run dev            # tsx watch src/index.ts

# frontend (port 5173, proxies /api -> localhost:3000)
cd client && npm run dev            # vite

# typecheck + build — MUST use these, not npx vite build
cd client && npm run build          # vue-tsc -b && vite build  (strict: noUnusedLocals)
cd server && npm run build          # tsc
```

- `client` build script runs `vue-tsc`, which fails on unused imports/vars. `npx vite build` alone skips typechecking and hides these errors — always verify with `npm run build`.
- Requires **Node 22.12+** (Vite 8 engine; <20.19 or <22.12 crashes). This box was shipped without Node — fresh install via `apt-get install nodejs` (nodesource bundle includes npm).
- There is **no automated test suite**. Verify backend by `curl localhost:3000` with a Bearer token. Login: `POST /api/v1/auth/login {username,password}` — seed accounts are `admin`/`sales01`/`user01`/`purch01`/`wh01`, all password `admin123`.

## Gotchas (hard-won)

- The only health endpoint is `GET /api/health` (mounted before auth in `src/index.ts`). Any other unknown `/api/v1/*` path returns `code: 500 "接口不存在"` — don't mistake that for a server failure.
- **Prisma is pinned to `5.22.0` — never "upgrade" it.** Prisma 7+/8 moved to a contract-based CLI that broke this project; it was intentionally downgraded, and `prisma.config.ts` was removed (not used in v5).
- **`npm start` / `node dist/index.js` is BROKEN**: `tsc` emits ESM with extensionless imports → `ERR_UNSUPPORTED_DIR_IMPORT`. Server is `"type": "module"`. Only `tsx` (dev) runs it. Fixing prod `dist` requires `.js` extensions or a bundler.
- **`MrpRun` has NO `createdAt` field** (it has `startedAt`/`completedAt`). Any `orderBy: { createdAt }` on `mrpRun` throws at runtime AND typecheck. (Two such bugs were fixed in `mrp.service.ts`/`dashboard.service.ts`.)
- SQLite DB lives at `server/prisma/dev.db` — the relative `DATABASE_URL="file:./dev.db"` in `server/.env` resolves to the schema dir, not the server cwd. Reset: delete `dev.db`, then `npm run prisma:migrate` + `npm run prisma:seed` (seed is idempotent upsert).
- Segfault-free restart pattern: `(setsid npx tsx src/index.ts > /tmp/log 2>&1 < /dev/null &)` — plain `nohup ... &` in a tool call can die with the shell.

## Architecture / conventions

- **API envelope**: every response is `{ code, message, data, timestamp }`, success `code: 200`. Frontend axios interceptor (client/src/api/request.ts) returns the whole envelope, so page code reads `res.data` (e.g. `res.data.items` for lists, `{total,page,pageSize,items}`).
- Backend layout: `server/src/{config,utils,middleware,routes,controllers,services}`. Routes declare required permissions via `requirePermission("module:action")` (e.g. `mrp:run`, `purchase:create`, `production:report`). New routes must be mounted with a permission + a matching method in `client/src/api/index.ts`.
- Blank base-entity CRUD is generated by `crudRoutes()` in `server/src/routes/base.routes.ts` (permission suffix `:view/:create/:edit/:delete`).
- Frontend api modules (client/src/api/index.ts) mirror backend paths exactly: `orderApi`→`/sales-orders`, `productionApi`→`/production/...`, `stockApi`→`/stocks`, etc.

## Adding a page (3 places, import path traps)

1. View: `client/src/views/<module>/<name>/index.vue`
2. Route: `client/src/router/index.ts`, `path` must match that directory
3. Menu: `client/src/layouts/MainLayout.vue` (menuItems array)

Import depth: from `views/<module>/<name>/index.vue` reach `src/api` as `../../../api`; but `views/login|home/index.vue` are one level shallower → `../../api`. `client` tsconfig is strict: no unused imports/vars allowed.

## Business flow (module ordering matters)

Orders must be **confirmed** (`confirmed`/`in_production`) before MRP sees them. MRP (`POST /api/v1/mrp/calculate`) expands BOM and outputs shortages + suggestions: raw/accessory shortages → purchase suggestions (convert via `POST /mrp/suggestion/generate-purchase`); semi/finished demand → production suggestions (`mrpApi.getRun(runId).result.productionOrders`). Then: create production orders → `POST /production/orders/:id/schedule` (requires an **active process route** for that product — else it throws) → generates work orders by process step → `POST /production/work-orders/:id/report` → auto-closes the production order and its sales order when all work orders complete. Purchase receipt (`PUT /purchase/:id/receive`) also stocks in materials.
